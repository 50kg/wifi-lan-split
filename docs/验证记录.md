# 验证记录与未覆盖项目

**简体中文** | [English](en/verification.md)

以下是在作者自己的电脑上做过的验证，环境是 Windows 10，手机热点 Wi-Fi 加公司网线。原始抓包和日志含有内网信息，不随源码公开。

## 断网与续租实测（2026-10-19）

- **内存模式断 Wi-Fi 抓包**：
  - 有线发送：Wi-Fi 在线时 4 包 / 239 字节，断开时 106 包 / 10708 字节；
  - 有线接收：分别为 28 包 / 3819 字节、219 包 / 166026 字节；
  - 计数器、原始 XML 和独立解析的 pcap 帧数及字节数都对得上。
- **断开 Wi-Fi 时的有线发送分类**：ARP 4、UDP 广播 3、到内网网关的 ICMP 1、到内网服务器的 TCP 98；没有观测到公网 IPv4、IPv6 或热点子网的包。公网的 HTTP/HTTPS/TCP/UDP/ICMP/IPv6 探测都失败；绑定有线网卡的 TCP 连接，在 WFP 记录里为拒绝。
- 断网测试前先设置了独立的 Wi-Fi 自动恢复；恢复后 HTTPS 返回 200，临时任务已清理。
- 加入路由看守后，做了三次真实的有线 DHCP 续租（其中一次通过工具后端）。每次检查时有线默认路由都是 0，看守日志记录了自动删除；Wi-Fi 保持连接，HTTPS 正常。
- **重启后一次性检查**：
  - 预检通过（SYSTEM 身份运行）：HTTPS 源地址为 Wi-Fi，远端 1.1.1.1；
  - 真实重启后，审计任务在开机约 1 分钟时生成正式报告，结果为 PASS；
  - 这是配置和代表性连接检查，不是开机全过程抓包。

磁盘/循环模式下出现过计数器和落盘帧数不一致，确有包没有写进原始记录，所以不能把那次的空记录当作“没有流量”的证据。同样的控制实验改用内存模式后，计数和帧数对得上，之后的正式断网测试都用内存模式。没有为了解决抓包问题去修改分流规则。

双网分流 · Windows 小工具

English version: User-Guide.en.md (in the program folder) / docs/en/user-guide.md (in the repository)

用途
Wi-Fi 连接手机热点，访问公网；网线只访问 192.168.x.x 内网，端口不额外限制。
热点自身的子网保留走 Wi-Fi，禁止从公司网线访问。
内网代理或隧道中转公网暂不处理。

使用
1. 把程序完整解压到一个固定文件夹，最好是只有管理员能写入的位置，例如 C:\Program Files\双网分流。双击“双网分流.exe”，接受管理员提示。
2. 打开后会自动检查一次，最上面一句话就是结论：
   · 绿色“分流已生效”：网线只能访问 192.168 内网，公网走 Wi-Fi。
   · 琥珀色：有一项需要处理，但网线暂时没有暴露，例如“路由看守没有运行”（防火墙仍在阻断）。
   · 红色：网线可能可以访问公网，例如“尚未启用分流”“‘USB 以太网’可以直接上公网”。
   结论下面写着原因和下一步。能自动修复时，会出现对应的按钮，例如“修复路由看守”。
3. 已经启用过的电脑，打开后看结论即可，不需要重新启用。
4. 第一次使用：先让 Wi-Fi 正常联网，再连接公司网线，关闭依赖固定出口的敏感软件，点击“启用分流…”。确认框会列出要改的设置，确认后才执行。
   运行工具之前还没有本工具的保护，插线本身就可能让 Windows 选择公司出口。要避免这段窗口，应由管理员预先部署防火墙。
5. “有线续租并验证”只在分流已生效时出现：只续租网线，不释放地址、不改 Wi-Fi，完成后核对默认路由和看守状态。
6. “还原设置…”会先确认，再停止看守、恢复备份里的网络参数。还原后网线可能重新可以访问公网，操作前请关闭敏感软件。
7. 断网时同样能运行工具和还原；也可以双击 Restore.cmd，输入 Y 确认后还原。必须保留完整的解压目录。
8. “打开数据文件夹”打开 C:\ProgramData\WifiLanSplit，里面是这台电脑的状态、备份和日志。启用、修复、续租、还原的完整输出在 last-operation.log，失败原因另记在 last-operation-error.txt。
   操作进行中关掉窗口不会中断它；再次打开时，如果它还没完成，会显示“另一项操作正在进行”，这时不能开始新的操作。
   不要把甲电脑的备份还原到乙电脑；还原会检查 Windows 安装标识和网卡 GUID。
9. 按 F5 或点“重新检查”可以再检查一次。“查看日志”展开本次打开以来的操作记录。

检查项的含义
· 防火墙阻断：网线只放行 192.168 内网，IPv6 全部阻断。检查的是实际规则的地址、协议、端口、程序和接口范围，以及所有网络类别的防火墙是否开启；不是只数规则条数。注明“仅限‘以太网’”时，规则只作用于这一块网卡。
· 网线默认路由：应为 0 条。DHCP 续租可能短暂补回一条，路由看守会自动清除。
· 路由看守：开机任务存在，心跳在 6 秒以内。
· 看守版本：正在运行的看守和这个版本不同时出现，可以点这一行的“更新”。更新时先准备好新程序，再替换并重新启动，开机任务保持不变；替换失败会放回原来的程序。
· 其他网线网卡：另一块网线网卡不在阻断范围内，或者有默认路由。
· 其他接口：Tailscale、VPN 等不在本工具控制范围。
检查只核对配置，不会断开 Wi-Fi，也不抓包。配置检查不等于实际流量证明。

适用范围
- Windows 10/11 64 位、Windows PowerShell 5.1、.NET Framework 4.x、Windows 自带防火墙。
- 新电脑首次设置要求恰好一张已连接的物理 Wi-Fi 和一张已连接的物理有线网卡。
- 网线保留 DHCP，需要取得 192.168.x.x 地址和 192.168.x.x 网关。
- Wi-Fi 已有正常的 IPv4 地址、默认路由和 IPv4 DNS。
- 两张网卡的子网不能重叠。
- 首次设置时，如果发现以下情况，会停止并说明原因，不擅自修改第三方连接：
  其他活动网络接口（VPN、Tailscale、Hyper-V/WSL/Docker 虚拟网卡）、已有的 /16 路由、公司策略禁用本地防火墙规则。
- 启用之后再连上的 Tailscale、VPN 等接口，工具不关闭也不配置它们，只在检查项里列出。
- 更换公司网关、热点、网卡或网络环境后，需要重新检查；热点子网变了时，界面会提示先还原再重新启用。

真实保护机制
第一层：防火墙。
- 网线阻止 192.168.0.0/16 以外的 IPv4 目的地址，阻止网线 IPv6；保留本地 DHCP 有限广播。
- 热点如果在 192.168.x.x 内，另外阻止网线访问热点子网。
- 规则匹配全部应用、协议和端口，覆盖正常 Windows 网络栈中的 HTTP/HTTPS、WebSocket、TCP/UDP Socket、QUIC、DNS 等。
- 阻断规则作用于所有有线接口。早期版本留下的规则组只作用于某一块网卡，仍会被识别；这时检查项会注明“仅限”哪块网卡。
- 原有入站防火墙规则仍然有效；“内网全端口”不等于关闭所有入站保护。

第二层：路由与看守。
- 公网默认路由优先走 Wi-Fi；192.168.0.0/16 的持久路由经公司网关走网线；更具体的热点直连子网仍走 Wi-Fi。
- 网线的 IgnoreDefaultRoutes 设为 Enabled，作为补充配置。作者电脑上实测，这个开关仍不能阻止 DHCP 续租后补回网线默认路由。
- 因此工具安装了轻量的本机路由看守：
  · 程序在受保护的 C:\ProgramData\WifiLanSplit\RouteGuard.exe，只有 SYSTEM 和管理员可以写入。
  · 计划任务 WifiLanDefaultRouteGuard 以 SYSTEM 权限随系统启动。
  · 通过 Windows IP Helper 接收 IPv4 路由变化通知，并每 500 毫秒检查一次。单次出错只记日志，不会退出；心跳只在检查成功后写，所以一直出错的看守会显示为“没有运行”。
  · 只删除指定网线网卡的 IPv4 0.0.0.0/0 路由，通过网卡 GUID 重新定位接口编号。
  · 不操作 Wi-Fi，不删除内网路由，不配置代理。
  · 界面关闭后看守继续运行；还原时停止任务、结束对应程序并卸载任务。

必须理解的边界
- 这是“DHCP 生成默认路由后自动清除”，不保证路由表里连一瞬间都不出现它。通知处理和兜底检查有延迟，系统启动到看守运行之前也有时间窗口。防火墙始终是阻止实际公网流量的主要保障，不能为了有看守而关闭防火墙。
- 如果必须要求 DHCP 客户端从不生成默认路由，需要公司 DHCP 服务端针对这台电脑不下发网关，或者使用经公司确认的无网关固定地址。本工具没有修改公司 DHCP 服务器。
- 网线只允许私网目的地址，不等于禁止内网代理替你访问公网。要限制这种中转，必须缩小允许的内网服务或约束服务端。
- 网线 DNS 改成了热点的 DNS，公司内网域名可能解析不了；内网服务请用 IP 访问。
- 虚拟机桥接、WSL/容器、额外 VPN、内核驱动和其他出口需要另行验证。
- 有管理员权限的软件、公司组策略或安全软件可以改变配置；本工具不是对抗管理员权限的隔离系统。

备份与还原
- 首次设置前，先保存状态、导出防火墙，再建立阻断规则和修改路由。原始备份不会被覆盖：备份目录里另有一份启用时的 state-at-setup.json。
- 本机备份按 GUID 匹配网卡，接口编号变化不影响身份识别；找不到网卡时拒绝猜测。
- 还原会删除本工具和原分流方案的规则，恢复原 DNS、接口开销、默认路由接收偏好和被移除的路由，并恢复原防火墙启用状态。
- 还原不自动导入整份旧防火墙，以免覆盖后来新增的无关规则；完整导出副本留给管理员应急。
- 设置中途失败时，保留已建立的阻断和备份，不自动撤销阻断，以免意外开放公司出口。界面会提示“上次启用没有完成”，请先还原再重新启用。
- 还原后再次启用会创建新的备份，不删除旧备份。

文件
- 双网分流.exe：原生 Windows 界面。运行前会核对下面三个后台文件，被改过就拒绝执行。
- RouteGuard.exe：后台路由看守。请勿单独双击，界面设置时会部署。
- backend.ps1 / network-core.ps1：可读的配置、检查和还原逻辑。
- Restore.cmd / Restore.ps1：离线还原入口。
- diagnostics\诊断PowerShell模块.cmd：只读诊断。界面提示某个命令“was found in the module …, but the module could not be loaded”时，用平时打开本工具的方式运行它（双击，或在同一个终端窗口里运行），把桌面上生成的报告发给开发者。
源码在项目的 src 目录；重新编译用项目根目录的 build.ps1。

这是本地生成的未签名工具。不需要下载运行库、浏览器或云服务，配置操作需要管理员权限。
